# App gaps: implementation briefs

Four features for Steam RetroAchievements, built one at a time in the main checkout. Each brief is written to be handed to an engineer who has not seen the conversation that produced it.

## Rules for every task

**Project.** A Swift 6 background app (macOS, Windows, Linux) plus one script, `steam/inject.js`, injected into Steam's UI over its local DevTools port. The script draws everything; the app does the rest, over the bridge in `Sources/RACore/BridgeHandler.swift`. Most users are on Windows, Steam Deck, Bazzite or EmuDeck, so a change that only works on macOS is not finished. Read `docs/steam-internals.md` before touching Steam-side code.

**How to work.**
- Write the failing test first, watch it fail, then write the least code that passes. Tests use Swift Testing and the fakes in `Tests/RACoreTests`.
- Run the suite with `scripts/test.sh`. `messageOverTheLimitEndsTheConnection` in `DevToolsSocketTests` already fails on the base commit; report anything else that fails.
- Reuse the codebase's helpers, then the platform, and add a dependency only if the brief allows it. No options or abstractions nobody asked for. A shortcut with a known limit gets a comment: `shortcut: <the limit>, <when to upgrade>`.
- Keep each platform working: use `#if os(...)` the way the surrounding code does. `node --check steam/inject.js` must pass.
- Update `README.md` where the feature changes what it says, in its plain style.

**Hard limits.**
- Do not commit, push, stash, switch branches, reset, or discard changes. Other work is uncommitted in this checkout and must be left intact, including the SteamGridDB artwork code (`Sources/RACore/SteamGridDB*.swift`, `addArtwork` in `inject.js`).
- Never read, print or log credentials: the RetroAchievements key in the Keychain or credentials file, or anything from `STEAMGRIDDB_API_KEY`. `Sources/RACore/SteamGridDBKey.swift` must stay empty.
- The Steam client on port 8080 is the user's real one. `node scripts/steam-eval.mjs '<expression>'` is allowed for read-only inspection. Do not restart Steam, add or remove shortcuts, change art, or sign in or out. Do not run `scripts/build-app.sh`, which replaces the installed app.
- Do not bump the version.

**Report back** in under 200 words: what changed, the test result, and exactly what could not be verified. Do not claim something works in Steam unless it was seen working there.

## Task A: Missable tags and beaten/mastered status

**Goal.** Warn players about achievements they can permanently miss, and show the award RetroAchievements gives for a game.

**Data.** `API_GetGameInfoAndUserProgress.php` needs `a=1` to return the award fields (`RAClient.gameProgress`). Expected, from memory, so check `api-docs.retroachievements.org`: `HighestAwardKind` is one of `mastered`, `completed`, `beaten-hardcore`, `beaten-softcore`, or null; each achievement has a `type` of `progression`, `win_condition`, `missable`, or null. Decode both as optional in `Sources/RACore/RAModels.swift`: progress cached before this change has neither, and an unknown value must not break decoding.

**Show.**
- A **Missable** tag on achievements that are missable and still locked, everywhere the app lists achievements with its own elements: the desktop game panel and hover cards, and the Big Picture list.
- In Steam's own views (achievements page and overlay, fed by `feedSteam` in `inject.js`), Steam draws the row, so prefix the description with `Missable: ` for those achievements.
- The award on the game page by the progress summary: **Mastered**, **Completed**, **Beaten (Hardcore)** or **Beaten**. Nothing when there is no award. Build the text in `PanelPayload.swift` the way `pointsText` and `hardcoreText` are built.

**Do not change** the perfect-game ribbon or how the percentage is counted. Unlocked achievements carry no Missable tag. Subsets use the same path as the base game.

**Tests.** Decoding with the fields, without them, and with an unknown value; the panel payload's award text for each kind; the tag only on locked missable achievements; `a=1` in the request.

## Task B: `.7z` and `.rvz` fingerprinting

**Goal.** Stop showing "Couldn't check this ROM version" for these two formats by fingerprinting them for real. `Sources/RACore/RomHasher.swift` lists `7z` as unsupported, and README's troubleshooting section says so.

**`.7z`.** `RomHasher.withIterator` handles zips by hashing the first entry. Do the same for 7z so that it works on all three platforms without an external tool: vendor the 7-Zip C decoder from the LZMA SDK (public domain) next to the existing `Vendor/libchdr/deps/lzma-26.02`, or into a new vendor target, compiling only the files needed. Add it to `THIRD_PARTY_NOTICES.md`. Arcade (27) and MS-DOS (26) keep their special handling, as with zips: read how rcheevos treats them first. Reject corrupt archives cleanly and cap the extracted size so a hostile archive can't exhaust memory.

**`.rvz`.** Dolphin's compressed GameCube/Wii format; `Vendor/libchdr` already has zstd and LZMA decoders. Check first what the vendored rcheevos does for consoles 16 (GameCube) and 19 (Wii), and whether it hashes through file callbacks that a reader can sit behind. The format is specified in Dolphin's `docs/WiaAndRvz.md`. Implement a reader only for the parts the hash needs. If Wii cannot be supported properly (for example because rcheevos has no Wii hash), keep the existing name-match message for Wii, say so in the report, and do GameCube.

**Fixtures.** Hash results must be compared with hashes of the same content in its plain form, so a wrong reader fails the test. Keep fixtures small: generate at test time where the tool exists, otherwise check in a tiny 7z, and build a minimal RVZ in the test from the spec. The test suite runs on Windows, Linux and macOS CI, so a fixture must not depend on a tool only one has.

**Stop and report** rather than ship a partial reader that returns wrong hashes: a wrong hash tells the user their ROM is unsupported when it isn't, which is worse than the current message.

## Task C: One-click updates

**Goal.** When a newer release exists, let the user install it with one click. Today `Sources/RACore/UpdateChecker.swift` only links to the release page. Nothing installs without a click.

**Where the click happens.** Read how `Sources/SteamRetroAchievements` (`AppModel`, `App`, `Tray`, `Headless`) shows update notices today and add **Update now** there: the macOS menu bar and the Windows tray. On Linux and Steam Deck there is no window, so add the button to the RetroAchievements dialog in Steam (`inject.js`, settings dialog), which then covers every platform through a bridge method.

**Security: this is a trust boundary.**
- Accept only the asset named for this platform (`steam-retroachievements-macos.zip`, `-windows.zip`, `-linux.tar.gz`) from this repository's latest release via `api.github.com`. Download over HTTPS from `github.com` or GitHub's release asset hosts only.
- The Releases API returns a `digest` (sha256) on assets. Verify the download against it; refuse to install if it doesn't match. If the field is missing, do not install: fall back to opening the release page.
- Extract into a new private temp folder. Reject archive entries that escape the folder (`..`, absolute paths, symlinks pointing outside).

**Installing.** Keep the user's data, sign-in and open-at-login entry. The new copy must be complete before anything is replaced, and a failure at any step must leave the old copy working.
- macOS: replace the `.app` bundle where it runs, then relaunch.
- Windows: a running `.exe` can't be overwritten but can be renamed. Rename the old files aside, move the new ones in, start the new copy (a new copy already replaces the running one), and delete the leftovers on next start. All the DLLs and `inject.js` in the folder are part of it.
- Linux and Steam Deck: replace the binary, `inject.js` and `icon.png` by rename, then restart; if it runs as the systemd user service, restart so that it stays under the service.
- If the install location isn't writable (or macOS app translocation applies), open the release page instead.

`URLSessionTransport`'s 30-second limit is too short for a 25 MB download on slow connections; use a longer limit for this download only.

**Tests.** Fake transport and temp folders: picks the right asset, rejects a wrong digest, a missing digest, a foreign host and path-escaping entries; a failure part-way leaves the old files in place. Do not exercise the real swap against an installed copy.

## Task D: Open Log and Copy Diagnostics

**Goal.** Make problem reports easy to act on. Add two buttons to the RetroAchievements settings dialog in `steam/inject.js`, near **Sign Out** and **Uninstall…**.

**Open Log.** Opens the log in the system's default viewer. Add a separate `BridgeActions` entry. Do not reuse `openURL` or widen `BridgeRouter.isAllowedExternalURL`: that check is a trust boundary. The page must not be able to choose the path. If the app already has a platform helper for opening things, use it. The log paths are in `Sources/SteamRetroAchievements/Log.swift`.

**Copy Diagnostics.** A new bridge method returns text built by the app, and the script copies it to the clipboard, showing "Copied". Include: app version, OS and version, Steam build if easily available, whether signed in (yes/no only), which emulators were detected, the bridge's connection state, and the last 100 log lines.

**Privacy: must be tested.** Never include the RetroAchievements key or username, the SteamGridDB key, or any URL query string. Replace the home folder path with `~` throughout, including in the log lines, because paths contain the OS account name. Scrub in the app, so the page never receives the raw text.

**Clipboard.** `navigator.clipboard` may not work in Steam's CEF pages. Check with a read-only `steam-eval` whether the API exists, use a hidden-textarea `execCommand("copy")` fallback, and if both fail show the text in the dialog, selected, for manual copying.

**Tests.** Scrubbing (key, username, query strings and home path removed, in log lines too), the 100-line limit, a missing log file, and that the page can't pass a path to Open Log.
